# PHASE 14 — PERFORMANCE & NAVIGATION OPTIMIZATION

### Objective

Fix the current approximately 3–4 second delay when moving between Visionix sections.

### Scope

* Measure navigation performance.
* Identify the actual bottleneck.
* Investigate repeated API requests.
* Investigate repeated profile/personalization requests.
* Investigate career-data requests.
* Investigate unnecessary component remounting.
* Investigate route loading.
* Investigate frontend bundle loading.
* Investigate backend response time.
* Investigate MongoDB query performance.
* Ensure AI calls are not triggered unnecessarily during navigation.
* Optimize only confirmed bottlenecks.
* Verify section-to-section navigation after optimization.

### Bundle optimization

* Introduce route-level lazy loading where appropriate.
* Reduce unnecessary initial JavaScript.
* Investigate the current large production bundle.
* Do not sacrifice functionality for bundle size.

### Success goal

Visionix should feel significantly faster and smoother when navigating between sections.

# PHASE 15 — PRODUCTION SECURITY & API PROTECTION

### Scope

#### CORS

* Replace permissive CORS behavior.
* Allow only configured/approved frontend origins.
* Ensure development and production environments work correctly.

#### Security Middleware

* Add appropriate security headers using Helmet.
* Add request-rate limiting.
* Add stricter request-size limits.

#### Authentication Security

* Review JWT handling.
* Review token lifetime.
* Review storage mechanism.
* Evaluate secure HTTP-only cookie architecture where appropriate.
* Preserve authentication functionality.

#### Input/API Security

* Review validation.
* Review authorization.
* Review public endpoints.
* Protect expensive AI/API endpoints from abuse.

#### Unsafe HTML

* Remove unsafe rendering of external YouTube titles/content.
* Render external text safely or sanitize it where genuinely required.

### Success goal

Visionix should have production-appropriate baseline API and browser security without breaking existing authentication.

# 🚫 PERMANENTLY OUTSIDE THE CURRENT ROADMAP

The following are intentionally removed from the active implementation roadmap:

* Live scholarship database.
* Daily scholarship updates.
* Scholarship deadline tracking.
* Scholarship deadline notifications.
* Live upcoming-exam calendar.
* Daily exam updates.
* Exam deadline tracking.
* Exam deadline notifications.
* Any system that claims continuously current scholarship/exam information without a reliable update architecture.

They may only be reconsidered in a future roadmap after a reliable data-update strategy is established.
